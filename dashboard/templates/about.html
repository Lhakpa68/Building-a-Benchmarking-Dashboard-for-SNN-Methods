SNN simulators and the methods considered
The dashboard compares five actual spiking neural network simulators. The measured backends, workload, and native learning objectives are stated so that the comparison is not detached from its experimental context.
Brian2

Equation-based simulation, including NumPy, Cython and compiled C++ modes; these are real Brian2 backends and differ in setup costs.

NEST

Point-neuron simulation using the measured one-, two- and four-thread execution configurations.

Nengo

Neural Engineering Framework reference backend, with a distinct native learning mechanism.

snnTorch

PyTorch-based spiking neural network training with surrogate gradients.

SpikingJelly

PyTorch-based spiking neural network library with alternative sequence and execution modes.

What this dashboard does not claim
The energy figure is a proxy, not a measurement. It is runtime × CPU utilisation × a configured TDP value, and is comparable only within this machine and this session. It is not joules at the wall socket.
The simulators are not solving identical problems. The tensor-based libraries run a discrete recurrence; the simulators integrate an ODE. The equivalence view bounds how far apart that lets the answers drift, but a runtime advantage is partly a cheaper problem, not purely better engineering.
One hardware platform, by design. Holding the machine fixed is what allows a difference in runtime to be attributed to a difference in the simulator rather than to the hardware it happened to run on — that control is the basis of the comparison. Running the same harness on GPU hardware is identified in the thesis as the next extension of this work.
