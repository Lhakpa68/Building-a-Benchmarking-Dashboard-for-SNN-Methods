{% set S = opt.softmax %} {% if S %}
Activation function
The output layer above gives each backend a weighted score y (lower is better). A softmax activation turns the scores of one profile into priorities that are positive and add up to 100%: each simulator is represented by its best eligible backend for that profile, and its priority is exp(−y/τ) divided by the sum of exp(−y/τ) over the simulators, with temperature τ = {{ '%g'|format(S.tau) }} (N={{ '{:,}'.format(S.network_size) }}, {{ 'share-of-total' if S.normalisation == 'share' else 'min–max' }} normalisation).

In plain words: a priority close to 100% means that the profile clearly prefers one simulator; similar priorities mean that two or three simulators are almost as good and the choice is close. The simulator with the highest priority is always the one whose backend is recommended above.

Softmax is monotone, so it never changes which simulator ranks first; it shows how far ahead that simulator is. Representing each simulator by its best backend means that a simulator is not favoured because it has more backends. A smaller τ sharpens the priorities and a larger τ flattens them; the value 0.1 is one tenth of the 0-to-1 range of the min–max scores, so a score gap of 0.1 divides the priority by e (about 2.7). Priorities are a presentation of the weighted scores, not probabilities that a simulator is truly best.

Calculation: {% if opt.normalisation == 'share' %}Share-of-total normalisation: each backend's runtime, memory growth and scaling exponent is divided by the sum over the eligible backends, and accuracy (if weighted) enters as its shortfall from 100% divided by the summed shortfalls, so that a smaller share is better on every criterion.{% else %}Min–max normalisation: inference runtime on a logarithmic scale; memory as the growth in peak process memory above the same backend's footprint at the smallest measured size; the scaling exponent linearly; and accuracy (if weighted) inversely.{% endif %} At N=100 memory growth is zero for every backend, so memory does not discriminate there. The rank sum adds each backend's rank (1 = best) on every active criterion without weights, as a weight-free cross-check. The weighted cost is the sum of four normalised criteria. An absent metric is never substituted with zero. Grid sensitivity: {{ opt.n_grid_points }} equally spaced priority combinations (0%, 25%, 50%, 75%, 100% that sum to 100%).
