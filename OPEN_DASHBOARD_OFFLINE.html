Dataset, calculations and scope

This file is generated from the supplied benchmarking project’s canonical SQLite dataset via its shared dashboard_data.py functions. It stores the measured backend values in this HTML, so no Python installation, server, external assets, network connection or new benchmark execution is required.

Eligible simulators: Brian2, NEST, Nengo, snnTorch and SpikingJelly. Brian2/NumPy is the real Brian2 Python execution backend. Control-only implementations are not ranked.

Inference: measured median wall-clock seconds at selected neuron count. Memory: recorded peak process RSS in MB. Scalability: regression slope of log runtime versus log neuron count. Accuracy: reported held-out MNIST accuracy on a separate native learning task; not comparable across different paradigms.

For each eligible set, log inference and log memory use min–max normalisation; scalability uses linear min–max costs; higher accuracy is inverted to a cost when enabled. Score = sum of effective importance × normalised cost. Normalised weights sum to 1. If the criterion has no spread, it contributes zero. Changing the eligibility set, workload or weights can change the winner.

Research limitations: This viewer is evidence inspection and decision support, not a new optimisation algorithm for SNN simulator implementations. Memory instrumentation differs between backend runtime processes; scaling fits can be weak; accuracy is trained under different objectives; no measured recommendation uncertainty, independent user study or new experimental campaign is claimed. The Flask app in the ZIP offers more views, exports and provenance than this portable offline fallback.
